## Findings addressed in this review

1. **Broken lint command:** Next 16 no longer provides the old `next lint` command. Replaced it with a focused Biome gate, wired into CI and `npm test`. This gate's limited scope is documented.
2. **Playback race:** An older URL request could replace a newer selection's URL or error. The player now aborts and disregards stale requests and binds the displayed URL to its rendition. Unit tests cover ordering and source wiring; this is not a live browser/network test.
3. **Inactive coursework actors:** Suspended, closed or deleted learner, verified guardian and assigned-author sessions could retain coursework access. Migration `20261281059000_coursework_inactive_actor_boundary.sql` adds account-status checks to the applicable submission, revision, attachment, master-file and learner study-export predicates, and locks the active profile for hand-in, grading and review writes. Tests exercise denial and restoration. Other account ownership paths and personal-export sections are not covered by this change.
4. **Account-closure wording:** The page previously promised broader name and coursework removal than the code establishes. It now distinguishes current answer text from retained revision snapshots and files, qualified support-name redaction, separate identity removal and potentially remaining sessions. This is a wording correction, not a new deletion mechanism.
5. **Child login attachment and recovery (follow-up):** An authenticated guardian could call the attachment RPC with an existing user ID without proving the trusted route created it. A lost response after an attachment could also cause the route to delete an identity that was already linked. New creation is paused at the route and the authenticated reservation and attachment grants are revoked by migration 600. Existing accounts are not automatically disabled; detachment does not revoke sessions or remove the authentication identity. A trusted and recoverable workflow still needs to be built and tested.

## Important remaining work

- **Keep assignments and cohorts off.** Database migrations and flags have not been deployed; existing enabled settings are preserved by the migrations and must be switched off explicitly in any existing deployment. The gates alone are not a complete safeguarding program.
- **Coursework files:** A direct authenticated confirmation RPC does not perform the web route's storage HEAD/size check. Malware scanning is absent. Historical mixed-purpose assets require review. Physical object deletion is separate from database scheduling/attestation and has not been verified end-to-end. Previously issued signed URLs may remain usable until expiry.
- **Closure and retention:** Earlier coursework revision snapshots and files may remain after adult account closure; the adult retention and safeguarding-hold interaction needs review. Exact display-name redaction does not establish that support replies contain no other identifying information. The identity-removal check observes the Supabase authentication table, not all possible external copies. There is no blanket session-revocation guarantee. Existing inactive owner appointments and a safe visual transfer/recovery workflow also need attention.
- **Concurrency and deployment:** These database tests use a single-connection emulator. Earlier minimal-schema PostgreSQL lock-order probes are useful but are not deployed-schema concurrency tests. Test on a representative PostgreSQL/Supabase deployment, including transactions, policies, storage and real browser sessions, before enabling sensitive features.
- **Operations and external dependencies:** Retention execution, actual object removal, owner bootstraps, notifications and delivery need verified operational workflows. A queue or acknowledgment is not evidence of delivery or case resolution. D3's storage budget and currency remain undecided; a usable price source is also needed. Other D1–D8 work and its dependencies remain in `docs/remaining.md` and `DECISIONS.md`.
- **AI and religious content:** Reviewed help is available, but the hosted site does not yet have a secure connection to the owner's PC model; no live model test was performed. A teacher must review quiz drafts. Calendar, prayer times, Quran sync and daily Ayah require verified sources, licences and scholarly/method review before claims of accuracy. Some blockers require owner decisions, trusted sources, operational setup or engineering rather than money.
- **Broader audit:** The current lint subset, duplicate scan, automated tests and static repository checks do not replace a complete security, privacy, accessibility, performance or legal review. Review remaining Biome diagnostics and other metadata, admin, media and nonprivileged-actor paths individually.
